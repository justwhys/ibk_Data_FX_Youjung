## 3. 추천 — C안

C안은 심사위원이 별도 설명 없이 **시장 상태 → 점검 순위 → ② 상담 준비**를 따라가기 가장 쉽다. 특히 1순위 섬유제품의 부담액 10억 원과 결제 예정액 1,042억 원, 당행 선물환 확인율 3%를 한 행에서 읽을 수 있어, 순위가 상담 판단으로 이어진다.

**추천을 뒤집을 조건**은 첫 화면의 주된 업무가 고객군 선택보다 **전체 결제가 몰리는 주를 파악하는 일**일 때다. 그 경우 B안의 전체 13주 결제 차트가 C안의 고객군별 미니 차트보다 목적에 직접 맞는다. 짧은 무설명 비교에서 B안이 1순위 고객군과 선정 기준까지 더 빠르고 정확하게 전달한다면 B안을 택할 근거가 된다.

## 4. C안 개선 제안

1. **결론 띠를 두 줄로 줄인다.** 첫 줄은 “비슷한 과거 100번 중 40번, 1주일 뒤 원/달러가 1% 넘게 변동”, 둘째 줄은 “평소 34번의 1.2배 · 1% 초과 상승 21% / 하락 19%”로 쓴다. A안의 평소 대비 배수를 가져오고 두 방향은 같은 크기와 색으로 표시한다.
2. **상단 우측의 4개 통화 미니 차트를 접고, 그 자리에 52억 원을 올린다.** 기준 원/달러는 상단 기준줄에서 확인할 수 있다. 52억 원 아래에 “결제 예정 5,684억 원 · 금액 기준 당행 선물환 확인 9%”를 배치하고 우측 세로 카드 세 장을 걷어낸다.
3. **① 표는 고객군 선택에 집중한다.** `13주 결제 흐름`과 `실적 증감`은 ②로 옮긴다. ②에서는 B안의 주차별 누적 막대를 활용해 선택 고객군의 결제일, 원화환산액, 당행 선물환 확인 여부를 읽을 수 있게 한다. `수입 결제형`은 표 위에 한 번만 표기한다.
4. **행마다 ‘상담 준비 →’를 실제 링크로 만든다.** 클릭하거나 키보드로 실행하면 기준일·필터·고객군을 유지한 채 ②를 연다. 첫 행의 고정 음영은 실제 선택 상태에만 쓰고, ‘나머지 23개’는 필터 적용 후 표시 가능한 고객군 수로 계산한다.
5. **경고등은 켜진 항목과 검증 링크를 앞세운다.** 결론 아래에 “유가 급변 켜짐 · 두바이유 한 달 −15%”를 남기고, ③ 링크에는 “두 기간 검증 결과 보기”라고 쓴다. 꺼진 두 항목은 중립색으로 짧게 표시한다.

## 5. 세 안의 공통 문제

- **관측 빈도의 분모와 비교 기준이 흐리다.** `40/100`은 유사 사례를 100건 기준으로 환산한 값임을 밝히고, 실제 표본 수 `265건`을 붙인다. `평소 34/100`의 모집단과 기간은 ③에서 정의한다. `21%`와 `19%`에도 유사 사례 전체가 분모임을 명시한다.
- **시장 변동과 고객 부담에 같은 ‘약 13원’을 쓴다.** 약 13원은 기준일 **원/달러**의 1%에 해당한다. 여러 결제 통화를 합산한 고객 지표에는 “각 결제 통화의 원화 환율 1% 상승 시 추가 부담”을 쓰고 금액 단위를 `억 원`으로 통일한다. 색도 주황은 부담·확인 안 됨, 경고등은 황색과 상태 문구로 역할을 고정한다.
- **업체 수의 집계 범위를 확인해야 한다.** TOP 5의 업체 수를 합치면 387개사로 전체 376개사보다 많다. 전체가 중복 제거 수이고 고객군 간 중복이 가능하다면 표에 명시하고, 고객군이 상호 배타적이라면 집계를 수정한다.
- **제출본에서 화면과 동작을 함께 검증해야 한다.** 현재 HTML은 공통 CSS·JS를 참조하고 예시 차트를 생성한다. 최종 단일 HTML에는 원천 데이터 기반 계산과 필터·탭 동작을 포함하고, 필터 적용 후에도 5곳 미만 고객군 숨김이 유지되는지 확인한다. 행내 PC의 실제 브라우저 표시 영역에서 표 하단과 이동 링크가 잘리지 않는지도 확인한다. [공통 레이아웃](/home/user/ibk_Data_FX_Youjung/wireframes/common.css:24)
